# IOP

**面向真实仪器设备和实验平台的研究环境。**

[English](README.md) · [安装](docs/runtime/README.md) · [Agent 接入](iop/connect/README.zh-CN.md) · [研究任务记录](docs/runtime/episodes.md) · [下载](https://github.com/Cherish0925/IOP/releases)

IOP 包含常驻 Runtime、仪器说明、驱动、实验平台配置、实验程序、数据记录和 Agent 连接。研究程序向同一个服务提交操作；服务协调仪器、执行串行与并行任务，并在 Agent 断开后保留实验及结果。

IOP 独立于 Agent 宿主运行。人、Agentic Research OS、Codex、Claude Code、Qiushi Engine 等通过相应的 SDK、HTTP 或 MCP 入口使用同一套实验能力。

## 安装与连接

使用 Python 3.10 或更新版本从源码安装：

```sh
python -m pip install "ai4instruments[agent] @ git+https://github.com/Cherish0925/IOP.git"
iop init
iop start
iop open
iop connect --name bench --local
```

安装桌面依赖后，`iop desktop` 可以打开原生桌面窗口。平台发行包包含 Python、Rust 执行器及 Runtime/Agent 核心依赖；已完成的构建列在[下载页面](https://github.com/Cherish0925/IOP/releases)。[安装说明](docs/runtime/README.md)覆盖 Windows、macOS、Linux、WSL 和远程实验室。

Agent 宿主可以安装 `iop connect` 生成的连接目录，或在兼容的 MCP 客户端中配置 `iop mcp`。支持本机、SSH 和远程 HTTP 服务。[连接说明](iop/connect/README.zh-CN.md)给出各宿主的具体方法。插件连接实验室服务，驱动和实验平台配置由该服务保留。Agent 从一份简洁的实验室概况和一段简短的工作方法开始，任务需要时再读取某台仪器的说明或某一部分工作的指南（`guide`，或终端里的 `iop guide`），每一轮携带的内容因此保持很小。

## 各部分负责什么

| 部分 | 职责 |
| --- | --- |
| 仪器 | 驱动或厂商 SDK、设备身份、单位、操作参数和实际读数，以及本装置对参数所能承受的界限。 |
| 实验平台 | 研究者或 Agent 配置真实连接、共享设备、样品信息和初始化流程。 |
| Runtime | 协调设备占用、依赖关系、并行分支、常驻程序、取消操作和结果存储。 |
| 研究程序 | 决定实验方法、算法、初始化条件、分析过程和任务反馈。 |
| 研究任务记录 | 保存初始观测、动作、后续观测和反馈，并关联已经完成的仪器操作。 |

设备发现不能代替样品准备和物理连接说明。独立的平台可以同时运行；共享设备由同一调度器协调。初始化需要明确执行，保存配置本身不会操作仪器。

## 操作

操作保留 [AI4Instruments](https://github.com/Cherish0925/AI4Instruments/blob/main/docs/operations.md) 定义的三类角色，每一类都是运行服务保存和执行的对象。

| 角色 | 在 IOP 中 |
| --- | --- |
| **Basic Operations** | 已登记设备的操作：每个是一项控制或观察，带参数、单位、范围和回读。 |
| **Standard Operations** | 由基础操作和标准操作组成并保存的方法，带参数、适用条件、具名结果和使用记录。 |
| **Workflow Operations** | 跨设备组织方法的保存流程：串并行的步骤图，或根据结果决定的程序。 |

带 `device` 的步骤是基础操作；不带的步骤按名称使用已保存的操作。运行服务将保存的方法展开为基础操作，记录每次使用，使方法可以查看、修改和复用。

| 研究任务 | 执行方式 |
| --- | --- |
| 扫描和细化区间 | `sweep` 汇集标量和数组结果。区间可以读取前序结果，自适应扫描根据已有读数安排后续点位。 |
| 估计波动或达到停止条件 | `repeat` 重复读数；`until` 根据阈值或汇集数据的不确定度停止。 |
| 优化测量响应 | `seek` 在声明的范围内搜索局部最大值或最小值。 |
| 继续中断的工作 | 显式 `retry` 重试符合条件的失败调用；停止的步骤图可以保留已完成结果并继续运行。 |

后续步骤可以绑定汇集的结果，例如功率最大的角度或拟合出的谱线中心。参数、组合方式和恢复行为见[操作](docs/runtime/operations.md)。

## 工作条件

平台写明目标实验需要的条件：观察、容差、依赖、校正方法与可选的有效期。`maintain` 用实验共用的操作和调度器执行这些方法。校正期间共同占用相互关联的设备，独立平台仍可继续工作。

实验用 `requires` 声明所需条件。运行服务在每个相关操作开始前查看已有条件状态，随结果保留当时的观察，并在后续发现漂移时标明相关时间段。`tune` 提供有范围限制的局部数值搜索，其他方法通过保存的操作和程序表达。分类和依赖均由具体平台配置。

仪器自身的条件（预热、过载、参考锁定等）写在设备记录里，也可以随型号说明提供，该型号的每台仪器接入时就带着这些条件；平台条件建立在它们之上。

声明了 `upkeep` 的平台由运行服务保持：设备空闲时，对未观察、待核对、即将过期或预计漂出容差的条件进行观察，并校正已漂移的条件。每一轮自动保持都连同原因一起记录，且不会安排需要人来做的步骤。任何实验（步骤图、连续实验或程序）都可以为其所需条件声明 `upkeep`：运行服务在实验内部，于操作之前恢复、在操作之间更新这些条件，数小时的扫描因此能一直保持只在几分钟内可信的对准。见[工作条件](docs/runtime/conditions.md)。

容差覆盖各领域工作点归结成的几种形式：数值范围；读数稳定，以多个读数的标准差、极差或漂移判断；与给定值一致，即仪器保持的设定值或标准器的标称值。平台写明操作者会报告的扰动，如开罩、更换样品，以及每个扰动作用的条件。指南 `priors` 按计量概念说明如何把操作者对平台的了解写成工作条件，并给出多个领域的例子。

每个读数都保留仪器对其有效性的说明：状态操作或状态查询、说明中写明的测量区间与饱和值、EPICS 告警和 OPC UA 状态码。不确定的读数与条件失效期间的数据一样标为存疑，扫描可重新测量。参数可带单位给出，在核对界限前换算到声明的单位；量纲不同的单位在调用仪器前即被拒绝。

## 测量数组

波形、谱线、图像、缓冲数据和数值流保留类型、形状、单位及坐标轴。`read_array` 返回有大小限制的摘要、曲线或二维图，也可读取选定窗口中的精确值。完整数组可下载为 NumPy 文件；复数数据可按模、相位、功率或分量读取。

视图可以定位峰、谷和阈值穿越点，拟合直线、洛伦兹或高斯谱线并给出标准误，也能沿二维图的每一行分析。Rust `iop-execd` 在服务进程之外处理大文件；Python 实现在规定大小范围内提供一致结果。

保存的操作可以将视图中的数值命名为结果，后续步骤据此绑定参数，工作条件据此核对或调节。见[读取数组](docs/runtime/drivers.md#reading-arrays--读取数组)。

## 测量方法

研究程序可用 `ai4instruments.iop.measurements` 计算流式均值和一阶不确定度传播。具名误差分量保留协方差：读数平均后，共享的校准误差仍然保留；取比值时，满足条件的公共增益误差会相消。估计值同时保留单位和带符号的灵敏度贡献。

[参考归一化测量程序](examples/iop/reference-measurement/) 支持配置实际的信号、暗信号和参考读数，保存原始采集，并在达到指定标准不确定度或样本数上限时停止。它通过现有实验接口保存进度，恢复时复用已完成的操作。适用假设和独立使用方法见[测量归约](iop/connect/skills/iop-lab/references/measurements.md)。

## 用于研究数据和学习

Episode 记录实验轨迹，与三类操作并存。Python、TypeScript 和 MCP 都可以保存任务与策略版本、观测、奖励、任务结束或外部中止信息。每条记录关联同一次实验中已完成的操作；重复提交相同序号返回原记录，重新连接后可以继续读取或导出 JSON Lines。整个实验可以保存为一个 ZIP，包含记录、文件和科研数据仓库可读取的 RO-Crate 说明。

创建 episode 不会重置设备。实验程序应明确准备步骤并记录实际初始状态；并行物理任务需要相应的独立资源。IOP 提供执行和数据能力，研究程序定义科学目标、反馈方式和学习算法。
