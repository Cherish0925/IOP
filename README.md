# IOP

**A research environment for physical instruments and experimental platforms.**

[中文](README.zh-CN.md) · [Install](docs/runtime/README.md) · [Agent connections](iop/connect/README.md) · [Python and HTTP](docs/runtime/http-api.md) · [Research episodes](docs/runtime/episodes.md) · [Releases](https://github.com/Cherish0925/IOP/releases)

IOP combines a persistent Runtime, instrument descriptions, drivers, platform configuration, experiment programs, data records and agent connections. A research program communicates with one service; the service coordinates devices, executes dependencies and retains the results when the agent disconnects.

The environment is independent of the agent host. People, Agentic Research OS, Codex, Claude Code, Qiushi Engine and other clients use the same registered instruments and saved experiments through the supported SDK, HTTP or MCP entry point.

## Install and connect

Install from source with Python 3.10 or newer:

```sh
python -m pip install "ai4instruments[agent] @ git+https://github.com/Cherish0925/IOP.git"
iop init
iop start
iop open
iop connect --name bench --local
```

`iop desktop` opens the native desktop entry point when its optional dependencies are installed. Platform release archives include Python, the Rust executor and the core service/agent dependencies. The [release page](https://github.com/Cherish0925/IOP/releases) lists available builds; the [installation guide](docs/runtime/README.md) covers Windows, macOS, Linux, WSL and remote laboratory hosts.

For agent hosts, install the connector directory generated by `iop connect`, or register `iop mcp` in a compatible stdio MCP client. Named connections support local services, SSH and remote HTTP. The [connection guide](iop/connect/README.md) documents each host's format. A plugin connects to the service; installing it does not replace instrument drivers or laboratory configuration.

## Organize one laboratory

| Part | Responsibility |
| --- | --- |
| Instruments | Installed driver or vendor SDK, identity, units, operation parameters and readbacks. |
| Platforms | Physical wiring, shared devices, sample information and initialization procedures supplied by the researcher or agent. |
| Runtime | Device ownership, dependency scheduling, parallel branches, persistent programs, cancellation and stored results. |
| Research programs | Scientific decisions, algorithms, initialization choices, analysis and task-specific feedback. |
| Episodes | Initial observation followed by actions, observations and feedback linked to completed instrument operations. |

Initialization is explicit. Discovery can identify supported interfaces and devices; it does not infer sample preparation or the physical meaning of every cable. Independent platforms can run concurrently. A shared device remains coordinated by the same scheduler.

## Operations

Operations keep the three roles defined by [AI4Instruments](https://github.com/Cherish0925/AI4Instruments/blob/main/docs/operations.md). Each is something the Runtime stores and executes.

| Role | In IOP |
| --- | --- |
| **Basic Operations** | The operations of a registered device: one control or observation each, with parameters, units, ranges and readbacks. |
| **Standard Operations** | Saved methods built from Basic and Standard Operations, with parameters, conditions, a named result and a record of use. |
| **Workflow Operations** | Saved organizations of methods across devices, in sequence and in parallel. Programs that decide from results call all three. |

A step with `device` is a Basic Operation; a step without it uses a saved operation by name. The Runtime expands it into its Basic Operations and records every use, so methods that worked accumulate in the laboratory and stay open to reading and revision. See [operations](docs/runtime/operations.md).

## Research and learning

Version 0.8.8 adds durable episode records to the existing experiment API. Python, TypeScript and MCP clients can save versioned task/policy identities, observations, rewards and termination information. Each transition links to completed operations in that experiment. Identical retries return the saved record; reconnection preserves the sequence. JSON Lines export supports downstream data processing and learning.

An episode does not reset equipment. Use an explicit preparation procedure and measured initial state. Parallel physical episodes require independent available resources. IOP provides execution and data; the research program defines the scientific task and the learning algorithm.
